# Quality check against the 10 rules (2026-11-01)

Checked on Windows 11 with JDK 21.0.12, Maven 3.9.11, Spring Boot 4.1.2 and PostgreSQL 18 from
embedded binaries (no Docker). Every test runs against a real database over HTTP.

## Rules

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | fixed | The only external calls are JDBC to each service's PostgreSQL. HikariCP bounds the wait for a connection (30 s default), but no statement had a time limit, so a lock wait (for example on a `stock` row) could hold a request forever. Every service now sets `spring.transaction.default-timeout: 10s` (`*/src/main/resources/application.yml`), which Spring applies to every JDBC statement in a transaction; test `transactionsHaveATimeout` in all three services. No swallowed errors in `src/main`; the one ignored `IOException` is in `test-support` when the embedded database closes at JVM exit. |
| 2 | Writes safe to retry | fixed | Payments and reservations were already idempotent per order (`ON CONFLICT (order_id) DO NOTHING`, tested with 20 concurrent duplicates). Defect found: a retried `POST /orders` (client timeout, proxy retry) created a second order and a second `OrderCreated` event. `POST /orders` now takes an optional `Idempotency-Key` header: a repeat returns 200 with the first order and writes no event, a key reused with a different body gets 422, and a malformed key gets 400. Tests: `aRetriedPostWithTheSameKeyReturnsTheFirstOrderAndNoSecondEvent`, `aKeyReusedForADifferentOrderIsRefused`, `malformedIdempotencyKeysAreRejected`, `concurrentRetriesWithOneKeyCreateOneOrder` (20 concurrent calls, 1 order, 1 event). Without the header the behaviour is unchanged. |
| 3 | No race conditions | pass | Shared state lives in PostgreSQL only: unique keys and `UPDATE ... WHERE available >= ?` make the read-modify-write atomic. Concurrent tests: 50 orders, 20 duplicate payments, 40 reservations on 5 units, and now 20 retries with one key. |
| 4 | Don't trust the clock | pass | `created_at` columns are `timestamptz DEFAULT now()` (stored in UTC). Nothing orders events by them; the M2 relay (Debezium) reads the outbox in commit order from the WAL, and the `created_at` index is only for cleanup. |
| 5 | Read before changing | pass | Config keys read by code: `payment.limit-cents` (in `payment-service/application.yml`) and the standard `spring.*` keys. `spring.transaction.default-timeout` is a Spring Boot property (`TransactionProperties`), checked by the tests above. |
| 6 | Never break compatibility | pass | The new migration `V3__order_idempotency_key.sql` only adds a nullable `idempotency_key` column with a unique constraint: existing rows and clients without the header are unaffected, and nothing is renamed or removed. The response body of `POST /orders` is unchanged. |
| 7 | One source of truth | pass | Each service owns its database and is the only writer (role tests); the outbox row is the single source for the event. Versions: Spring Boot 4.1.2 and JDK 21 agree in `pom.xml`, README and CI. |
| 8 | Small changes, no secrets, validate input | pass | Test passwords are random per run (`EmbeddedDatabases`); no secrets in the repo. Bodies are validated with Bean Validation (400 on bad input, including SQL-shaped SKUs); the new header is checked against `[A-Za-z0-9_-]{1,64}`. |
| 9 | Tests that can actually fail | fixed | No skipped or assertion-free tests. 15 hand mutations below: 9 of 10 original mutants were killed before; the survivor got a test. |
| 10 | Re-verify | pass | `mvn install` (compile and `verify`): order 13, payment 8, inventory 8 tests, 0 failures. `osv_audit.py Maven` on `mvn dependency:list -DincludeScope=test`: `100 dependencies checked, 0 with known vulnerabilities`. `audit_repo.py outbox-saga-orchestrator`: `OK`. |
