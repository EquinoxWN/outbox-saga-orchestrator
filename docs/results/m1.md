# M1 test results

Recorded 2026-10-04 on the author's machine (Intel Core i7-13700H, Windows 11, JDK 21.0.12, Maven
3.9.11, Spring Boot 4.1.1, PostgreSQL 18.6 from embedded binaries). CI runs the same `mvn verify` on
JDK 21 on ubuntu-latest.

## Tests: 22 passed, 0 failed

Command: `make test` (`mvn verify`). Each service module starts one real PostgreSQL, creates the
three databases and roles from `test-support/src/main/resources/db/init.sql` with random passwords,
runs Flyway as the service's own role, and tests over HTTP on a random port.

## Two test mistakes caught on the way

- The helper that runs `init.sql` split statements on `;` before removing comments, and the header
  comment contains a `;`. Fixed by stripping comments first.
- `new Object()` was meant to make the event write fail, but Jackson 3 serialises it as `{}`. The
  test now uses a payload whose getter throws, so it really exercises the failure path.

## Quality control (DMAIC)

| Phase | This repository |
|---|---|
| Define | When a service commits a change and publishes its event separately, a crash loses the event or announces a change that rolled back, and services disagree for good; this affects backend engineers splitting a system into services that own their databases. M1 counts when order, payment and inventory each own a database and role, every state change and its event commit in one local transaction, the outbox writer refuses to run outside a transaction, and payments and reservations are idempotent with no overselling ([RFC 0001](../rfc/0001-design.md)). |
| Measure | `make test` (`mvn verify`) against a real PostgreSQL 18.6 from embedded binaries on an Intel Core i7-13700H with Windows 11, plus an OSV.dev check of all 100 resolved Maven dependencies in the 2026-10-06 recheck. 22 tests passed (order 8, payment 7, inventory 7), 0 failed; 50 concurrent orders gave 50 events, 20 duplicate payments gave 1 decision, and 40 reservations against 5 units reserved exactly 5. |
| Analyze | Two test defects were found: the `init.sql` helper split statements on `;` before removing comments, and the header comment contains a `;`; and the failing-payload test used `new Object()`, which Jackson 3 serialises as `{}`, so the failure path was never exercised. The recheck found known advisories in `tomcat-embed-core` 11.0.24 and Jackson 3.1.5, the versions Spring Boot 4.1.1 manages. |
| Improve | The helper now strips comments first, and the test uses a payload whose getter throws. The parent POM pins Tomcat 11.0.26 and Jackson 3.1.7; the tests pass and the OSV.dev check then found no advisories. |
| Control | The `ci` workflow's `build` job runs `make ci` (`mvn compile` of every module and `mvn verify` with all 22 tests on JDK 21) on every push and pull request; `make audit` runs OSV-Scanner on a CycloneDX SBOM of every resolved Maven dependency on every push (added 2026-10-07, so the OSV.dev check is no longer manual), and Dependabot proposes updates weekly. In the code, `OutboxWriter.append` uses `Propagation.MANDATORY` (ADR 0002), Bean Validation rejects bad bodies with 400, SKUs are limited to `[A-Z0-9-]`, queries are parameterised, and each service role is refused by the other databases (SQLSTATE 42501). |
